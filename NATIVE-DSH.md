# Native DeepSeek Harness (DSH) backend

This contribution adds DSH to the existing ComfyUI MCP orchestrator. It uses
the official ACP client SDK and `dsh --profile acp`; it does not install a DSH
bridge plugin or attach to DSH's Web server. A companion Agent Panel change
adds the picker, token readout and stream-segment presentation.

## Setup and ownership

Install/configure DSH on the **orchestrator host**, including a working provider.
Start ComfyUI MCP normally and select DSH in the companion panel. A ComfyUI
container's filesystem or authentication probe cannot establish the host CLI's
login state: the orchestrator discovers the CLI and probes its model catalog.

For a portable installation, set `COMFYUI_MCP_DSH_BIN` to the CLI executable or
its absolute JavaScript entry and `COMFYUI_MCP_DSH_HOME` to the existing data
home. Otherwise discovery checks PATH, standard paths, a validated installation
hint, and same-user running DSH processes on Linux. It does not download DSH.
DSH reads its own credentials; the adapter does not forward credential values
to the browser or include them in arguments or diagnostics.

A fresh/default ACP profile may reuse already-installed official components and
an already-selected Mnemon bundle. Customized profiles are left intact. A
temporary per-process overlay establishes the selected provider/model and
startup dependency on settings. Catalog-only probes disable Mnemon in that
temporary process so enumerating models does not create idle-review agents.

ComfyUI owns execution. Do not execute the same session simultaneously in DSH
Web. The adapter prevents duplicate owners within this orchestrator process;
that is not a cross-process lock. The upstream panel's shared-conversation rules
still apply: a new browser tab is **not an isolated test conversation**. Use an
independent orchestrator/port or injected ACP fixtures for acceptance tests.

## Behavior

- Standard ACP session creation/resume, streamed thought/text, tool lifecycle,
  model and reasoning-effort selection, permission requests, cancellation and
  teardown. Unsupported options follow the capability/configuration advertised
  by the installed DSH runtime. Model switches reconnect and resume the same ID
  so image capability negotiation matches the route.
- Failed resume does not create a replacement session. An uncertain connection
  outcome is not automatically replayed. Errors retain the session and explain
  that existing generation receipts must be checked before resubmission.
- Incoming images require advertised vision capability, a bounded 60-second
  fetch, resizing to at most 1024 pixels, and a 4 MiB submitted-turn budget.
  Blind mode blocks image delivery and requires a fresh session when old history
  may contain images. Audio input is not advertised. The turn budget is not a
  guarantee about the size of a provider request containing older history.
- DSH alone gets the compact ComfyUI MCP router even if the shared environment
  requests full mode. Tools remain discoverable through list/describe/call. The
  panel server also uses its compact HTTP surface.
- `panel.persona.dsh` is a separate editable prompt. Its default keeps canvas
  operations on panel tools and loads detailed skills on demand. The final
  append, including environment/capability notes, is limited to 8 KiB. An
  oversized override reports an error rather than truncating messages. The
  preamble is injected once for a new session, not again on resume.
- ACP usage reports carry raw usage, capacity, ratio and session identity.
  The ratio is clamped for the circle; the raw count remains available. Cached
  snapshots are scoped to the session. Updates occur when ACP supplies usage,
  not by guessing tokens from streamed characters.
- Tool-call boundaries close the preceding stream segment. Pre-tool progress
  and the final answer receive different IDs, so the final summary is not
  painted into an earlier thought bubble. Thought-only segments have an explicit
  close event; pre-tool text has an execution-detail marker.

This contribution adds no remote history-deletion endpoint, private DSH RPC,
provider billing override, permission bypass, model download or node installation.
The existing runtime memory and compaction mechanisms remain DSH's responsibility.

## Validation and limits

The targeted tests cover discovery, profile preservation, repeated model probes,
session ownership, failed resume, no replay, model capability renegotiation,
prompt isolation, size limits, usage updates and ordered stream segments.
Run `npm run build` and `npm test` before merging.

Historical deployment measurements, **not benchmarks generated by this PR's CI**:
on the same model/workspace and a short no-tool request, first-request input
including cache reads fell from 78,352 to 18,322 tokens (76.6%). Initial ComfyUI
tool declarations fell from 41 to three routers; all 38 business tools remained
discoverable. The final panel append was 5,970 UTF-8 bytes. Different memories,
tools, prompts and provider tokenization change these numbers.

The production prototype was checked against DSH 0.1.5-rc.1. It also includes
deployment-specific patches that are **not part of this contribution**, including
server service setup, custom background-conversation switching, host model-path
mapping and provider-catalog maintenance. No production configuration, private
conversation, credentials, model weights or generated media is included here.
