<Note>
  **이제 Comfy Registry에 등록되었습니다.** ComfyUI-Manager에서 **ComfyUI Agent Panel**
  (`comfyui-agent-panel`)을 설치하거나, 최신 빌드를 원한다면 git으로 설치하세요
  (아래 [설정](#설정) 참고).
</Note>

**[comfyui-mcp-panel](https://github.com/artokun/comfyui-mcp-panel)**은 ComfyUI 사이드바에
자율 에이전트를 심어 넣습니다. 이미지, 워크플로우, 변경 사항을 요청하면 실제 ComfyUI를
대상으로 작업하고 그 자리에서 답합니다. 제공자를 선택하면 — **Claude**, **ChatGPT**,
**Gemini**, 또는 **Ollama(로컬)** 중에서 — 해당 에이전트가 백그라운드에서 실행됩니다:
구독 제공자는 **API 키가 필요 없고**, 로컬 모델은 **계정 자체가 필요 없습니다**(Ollama
백엔드는 호스팅된 OpenAI 호환 엔드포인트에도 접속할 수 있습니다). 매트릭스는
[백엔드](/docs/backends)를, 각 모델 등급이 실제로 어떻게 동작하는지는
[LLM 아레나](/docs/arena)를 참고하세요.

```
you ⇄ panel (pick a provider) ⇄ loopback bridge ⇄ panel orchestrator ⇄ background agent: Claude · ChatGPT · Gemini · any LLM
```

구독 제공자는 **API 키도, 토큰당 과금도 없으며** — 로컬 모델은 완전히 무료·오프라인으로
동작합니다. 에이전트는 디스크에 저장된 로그인 정보로 인증합니다(Ollama의 경우 그냥
로컬 데몬과 통신합니다). 오케스트레이터 하나가 루프백 브리지 포트 하나
(`ws://127.0.0.1:9199`)에서 모든 제공자를 서비스하며, 각 패널 탭은 핸드셰이크
시점에 자신의 제공자를 선택합니다. 브리지는 루프백 전용이며, 패널은 그래프 명령의
**고정 허용 목록**만 실행합니다(임의의 JavaScript는 실행하지 않습니다).

<Note>
  처음이신가요? [백엔드 / 제공자](/docs/backends)에서 선택 UI, 제공자에 중립적인
  `AgentBackend` 포트, 기능 매트릭스(Claude와 ChatGPT 사이에서 동일한 부분과 다른
  몇 가지 차이)를 설명합니다.
</Note>

## 설정

1. **팩 설치** — ComfyUI-Manager에서 `comfyui-agent-panel`을 검색하거나, git으로
   설치하세요:

   ```bash
   cd ComfyUI/custom_nodes
   git clone https://github.com/artokun/comfyui-mcp-panel
   ```

   <Warning>
   **Manager의 버전 드롭다운에서는 `Nightly`가 아니라 `Latest`를 선택하세요.** 이름과
   달리 Manager의 **Nightly**는 매일 밤 빌드되지 않습니다: 설치 시점에 저장소를 **한
   번만** 복제한 뒤 그 브랜치를 다시는 추적하지 않습니다. 그날 `main`이었던 커밋에
   그대로 고정되는 반면 `Latest`는 릴리스마다 함께 갱신됩니다 — 그래서 Nightly는
   보통 Latest보다 *더 오래된* 상태이며, 방치할수록 조용히 더 뒤처집니다. 업데이트가
   없다고 표시되는 이유는, Nightly 입장에서는 실제로 업데이트가 없기 때문입니다.

   실제로 어느 지점에 있는지 확인하려면 **Node Pack Info → Version**의 SHA를
   [저장소 커밋 기록](https://github.com/artokun/comfyui-mcp-panel/commits/main)과
   비교하세요. 벗어나려면 같은 드롭다운에서 `Latest (x.y.z)`를 선택하거나 — git으로
   유지하고 싶다면 — `custom_nodes/comfyui-mcp-panel`에서 `git pull`을 실행하세요.
   깔끔하게 fast-forward됩니다.
   </Warning>

2. 백그라운드 에이전트가 사용자의 구독을 쓸 수 있도록, **원하는 제공자에 한 번
   로그인**하세요:

   ```bash
   claude        # Claude — or: claude setup-token
   codex login   # ChatGPT (Codex)
   ```

3. 자신의 컴퓨터에서 **오케스트레이터를 시작**하고 계속 실행해 두세요 — 자세한
   내용은 [패널 오케스트레이터 시작하기](/docs/ko/installation#3-패널-오케스트레이터-시작하기)를
   참고하세요:

   ```bash
   npx -y comfyui-mcp@latest connect
   ```

4. **ComfyUI를 재시작**하고 **에이전트** 탭을 연 다음 **제공자를 선택**하고(Claude /
   ChatGPT 칩), **연결**을 클릭하세요. 패널이 오케스트레이터의 루프백 브리지에
   연결됩니다. 요청을 입력하면 에이전트가 응답합니다. **연결 해제**를 누르면 연결이
   끊기지만, 오케스트레이터는 사용자가 멈출 때까지 계속 실행됩니다.

`claude mcp add`도, API 키도 필요 없습니다. 패널은 순수 프런트엔드 확장 기능이라
오케스트레이터를 직접 실행할 수 없으므로, 오케스트레이터는 언제나 사용자가 직접
시작하는 프로세스입니다 — 패널은 이미 실행 중인 브리지에 자동으로 연결할 뿐입니다.
필요 조건은 PATH에 있는 Node.js/`npx`와 위에서 설명한 제공자 로그인뿐입니다. 브리지
포트는 `COMFYUI_MCP_BRIDGE_PORT`로 바꿀 수 있습니다.

<Note>
**원격 ComfyUI를 다루시나요?**(클라우드 GPU 파드, LAN의 다른 컴퓨터 등) 위 설정
과정은 그대로 적용되지만, 오케스트레이터는 원격 컴퓨터가 아니라 **자신의 컴퓨터에서**
실행하세요: `npx -y comfyui-mcp@latest connect <remote-url>`을 실행하면 파드의
HTTPS 페이지로 이어지는 보안 터널을 포함해 나머지를 알아서 처리합니다. 그런 다음
패널에서 연결을 클릭하세요. 전체 절차는 [클라우드 배포](/docs/cloud-deployment)를
참고하세요.
</Note>

<Note>
  **제공자 온보딩.** 연결 시점에 패널은 각 제공자의 준비 상태를 확인합니다(PATH에
  CLI가 있는지 + 디스크에 로그인 정보가 있는지 — macOS 키체인도 함께 처리됩니다).
  온보딩 카드는 **어느 제공자도** 로그인되어 있지 않을 때만 나타납니다. 저장된
  선택이 사용할 수 없는 상태라면 패널이 **준비된 제공자로 자동 전환**하며(저장된
  선호는 유지됩니다), 준비되지 않은 제공자의 행에는 일회성 `claude` / `codex login`
  단계를 시작해 주는 **"설정"** 작업이 표시됩니다. 자세한 내용은
  [백엔드 → 준비 상태 및 온보딩](/docs/backends#connect-time-readiness--onboarding)을
  참고하세요.
</Note>

## 할 수 있는 일

에이전트(Claude 또는 ChatGPT)는 comfyui-mcp의 모델 스킬(IDEOGRAM, WAN, LTX, Qwen
등)을 불러오므로, 사용자가 다루는 모델을 이미 알고 있습니다 — Claude는 네이티브로,
ChatGPT는 같은 지식을 MCP 도구로 노출한 형태로 이용합니다
([지식 동등성](/docs/tools/skills-knowledge)). 이미지·동영상·오디오를 생성하고,
ComfyUI를 살펴보고 관리하고, 사용자의 설정에 대해 추론한 다음 패널 채팅으로 답할
수 있습니다.

또한 **워크플로우나 설치 팩 전체를 한 번에 불러올 수** 있고
(`panel_load_workflow pack:<name>`) **비용을 고려**합니다: 번들 팩은 로컬 GPU /
무료이며, 즉석에서 만든 그래프의 경우 에이전트가 런타임을 확인하고(`list_packs`에
`action:"check_runtime"`) **유료 API 크레딧을 쓰기 전에 먼저 물어봅니다**. 자세한
내용은 [스킬, 팩 & 런타임 비용](/docs/tools/skills-knowledge)을 참고하세요.

## 실시간 그래프 조작

자율 에이전트는 `panel_*` 명령의 **고정 허용 목록**을 통해 실제 ComfyUI를 조작합니다
— 임의의 JavaScript는 실행하지 않습니다. 모든 그래프 변경은 LiteGraph의 변경 추적을
거치므로 **Ctrl+Z**로 되돌릴 수 있습니다. 동일한 `panel_*` 표면이 두 백엔드에 똑같이
노출되므로(Claude는 인프로세스, ChatGPT/Codex는 루프백 HTTP MCP를 통해)
[패리티](/docs/backends)가 자동으로 유지됩니다.

### 읽기

| 도구 | 동작 |
|---|---|
| `panel_query_graph` | 보고 있는 그래프를 조회 — 필터링/순회/집계, 토큰 한도 내에서 |
| `panel_get_subgraph` | 서브그래프 노드 내부의 그래프를 읽기 |
| `panel_view_selected` | 사용자가 **선택한** 노드를 읽기 — 한 번의 호출로 "이 노드"에 답함 |
| `panel_view_nodes_in_viewport` | **화면에 보이는** 부분만 읽기(뷰포트 사각형 + 줌) — 큰 그래프에서 작업 범위를 좁힘 |
| `panel_get_errors` | 노드가 빨간색인 **이유** — 오류가 난 각 노드를 원인과 연결(누락된 모델 + 다운로드 URL, 누락된 미디어, 유효성 검사, 런타임 `exception_type`) |
| `panel_list_workflows` | 열려 있는 워크플로우 탭과 현재 활성 탭을 나열 |
| `panel_list_nodes` | 설치된 커스텀 노드 팩을 나열 |
| `panel_list_mcp` | 연결된 MCP 서버를 나열 |
| `panel_get_content_mode` | 성인 콘텐츠(NSFW) 동의 상태를 읽기 |

### 그래프 편집 (되돌리기 가능)

| 도구 | 동작 |
|---|---|
| `panel_add_node` | class_type으로 노드를 추가 |
| `panel_remove_node` | 노드를 제거 |
| `panel_connect` / `panel_disconnect` | 이름이나 인덱스로 슬롯을 연결/해제(`panel_connect`에서 두 슬롯을 모두 생략하면 타입으로 자동 매칭; `auto_match:false`는 예전의 인덱스 0 방식으로 되돌림) |
| `panel_set_widget` | 위젯 값을 변경(steps, cfg, prompts 등) |
| `panel_edit_node` | 하나 이상의 노드를 원자적으로 이동/크기 조절/제목 변경/색상 변경/모양 변경/접기/고정 |
| `panel_auto_layout` | 링크 토폴로지를 기준으로 그래프 전체(또는 일부)를 깔끔한 흐름/격자 레이아웃으로 자동 정렬 — 미리보기는 `dry_run` |
| `panel_clear` | 모든 노드를 제거 — 전체 삭제도 Ctrl+Z 한 번으로 되돌릴 수 있음 |

### 서브그래프

| 도구 | 동작 |
|---|---|
| `panel_select_nodes` | 캔버스에서 노드를 선택(다중 선택) |
| `panel_create_subgraph` | 선택한 노드를 서브그래프로 묶기("Convert to Subgraph") |
| `panel_enter_subgraph` | 서브그래프 안으로 들어가 내부 노드를 읽거나 편집 |
| `panel_exit_subgraph` | 상위 / 루트 그래프로 돌아가기 |

### 공간 배치

에이전트는 노드의 기하 정보를 볼 수 있습니다 — `panel_query_graph`의 상세 행은 각
노드의 `pos`/`size`, 서브그래프 입출력 `rails`, `groups`, 노드별
`color`/`collapsed` 값을 반환하며, 이에 대응하는 쓰기 작업으로 캔버스를 배치한
다음 결과를 **스크린샷으로 찍어** 자신의 레이아웃을 스스로 판단합니다.
`workflow-layout` 스킬은 이를 의존성 기반 계층형 배치와 겹침 없는 자동 레이아웃으로
엮어내며, 그 핵심 규칙은 *입력과 출력을 항상 드러내 두어* 바로 이어서 작업할 수
있게 하는 것입니다.

| 도구 | 동작 |
|---|---|
| `panel_move_rail` | 서브그래프의 입력/출력 레일을 옮겨 경계선 배선을 짧게 유지 |
| `panel_create_group` / `panel_move_group` / `panel_edit_group` / `panel_remove_group` | 이름표가 붙은 그룹 박스를 생성/이동/제목·색상 변경/삭제(`node_ids`를 넘기면 자동으로 감쌈) |
| `panel_screenshot` | 캔버스를 PNG로 렌더링해 이미지로 돌려주어 에이전트가 레이아웃을 확인할 수 있게 함 |

### 워크플로우 탭

| 도구 | 동작 |
|---|---|
| `panel_new_workflow` | 새 탭에 빈 워크플로우를 열기(현재 탭은 절대 지우지 않음) |
| `panel_open_workflow` | 경로/파일명으로 워크플로우 전환 |
| `panel_rename_workflow` | 워크플로우 이름 변경 |
| `panel_close_workflow` | 탭 닫기(저장하지 않은 변경 사항이 있으면 강제하지 않는 한 거부) |
| `panel_save_workflow` | 프로그램적으로 저장/다른 이름으로 저장 — 대화상자가 뜨지 않음 |

### 워크플로우를 한 번에 불러오기

| 도구 | 동작 |
|---|---|
| `panel_load_workflow` | 한 번의 호출로 실제 그래프를 전체 워크플로우로 교체 — JSON을 채팅으로 주고받지 않고 번들 설치 팩의 로컬 GPU 워크플로우를 불러오려면 `pack:<name>`을 쓰는 편이 좋습니다. 교체되기 전 그래프는 되돌리기 지점이 됩니다(Esc 두 번 / `/revert`). |

### 지식 및 비용 인식

에이전트는 번들로 포함된 전문 지식을 찾아내고, 크레딧을 쓰기 전에 런타임 비용을
확인합니다(두 백엔드 모두 동일한 도구 사용 — 자세한 내용은
[스킬, 팩 & 런타임 비용](/docs/tools/skills-knowledge) 참고):

| 도구 | 동작 |
|---|---|
| `list_packs` (`action:"skill_list"` / `action:"skill_read"`) | 번들로 포함된 모델 계열 + 워크플로우 스킬을 찾고 읽기 |
| `list_packs` (`action:"list"` / `action:"read_workflow"`) | 원커맨드 설치 팩(로컬 GPU / 무료)을 나열하고 팩의 그래프를 읽기 |
| `list_packs` (`action:"list_templates"`) | 연결된 서버의 공식 ComfyUI 워크플로우 템플릿을 나열 |
| `list_packs` (`action:"check_runtime"`) | 그래프를 **local**(무료) 또는 **api/mixed/unknown**(유료)으로 분류 — 에이전트는 유료 API 크레딧을 쓰기 전에 먼저 물어봄 |

### 실행 및 보기

| 도구 | 동작 |
|---|---|
| `panel_run` | 열려 있는 워크플로우를 대기열에 추가(Queue Prompt를 누르는 것과 동일) |
| `panel_canvas` | 화면 맞추기, 노드 중심으로 이동, 이동(pan), 확대·축소 |

### 커스텀 노드 (내장 ComfyUI Manager)

## 되감기 및 롤백

지난 메시지는 고정되어 있지 않습니다. 아무 메시지에나 마우스를 올리면 나타나는
**✎ 편집** 버튼을 누르면 롤백 모달이 열립니다: **코드**를 롤백(그래프를 해당 턴의
스냅숏으로 되돌림)하거나, **대화**를 롤백(세션을 그 지점으로 포크)하거나, **둘 다**
롤백한 다음 그 지점부터 수정한 메시지를 다시 보낼 수 있습니다. 그래프 되돌리기는
턴별 스냅숏을 사용하므로, 한 턴을 되돌리면 그 턴이 시작된 시점의 그래프가 정확히
복원됩니다.

흔한 경우는 단축키 두 가지로 처리됩니다:

- **`/revert`** — 마지막 턴의 그래프 편집을 되돌립니다.
- **Esc 두 번** — 마지막 턴을 빠르게 되감습니다: 그래프를 되돌리고 메시지를 입력창으로
  불러와 수정한 뒤 다시 보낼 수 있습니다.

<Note>
  **코드**(그래프) 롤백은 **두 제공자 모두**에서 동작합니다 — 오케스트레이터 안의
  턴별 스냅숏으로 구현되어 있습니다. **대화** 롤백(과거 턴으로 채팅을 포크하는 것)은
  현재 **Claude 전용**입니다. ChatGPT/Codex 백엔드는 스레드 전체만 재개할 수 있어
  패널이 이 범위를 막아 둡니다. 자세한 내용은
  [기능 매트릭스](/docs/backends#capability-matrix)를 참고하세요.
</Note>

## 대기 메시지 트레이

에이전트가 바쁠 때 입력해도 메시지가 채팅 속에 묻히지 않습니다 — 다운로드 트레이
위에 고정된 **대기(Pending)** 트레이에 채팅 흐름과 별도로 대기합니다. 대기 중인
메시지마다 **편집**, **즉시 전송**, **삭제** 버튼과, 에이전트가 메시지를 처리하는
순서를 **재정렬**할 수 있는 끌기 핸들(≡, 왼쪽)이 있습니다. **즉시 전송**은 현재
턴을 중단시켜 바로 방향을 바꿉니다. 대기 중인 메시지가 큐에서 빠지면 채팅
**맨 아래**에 나타나므로, 전체 기록이 에이전트(Claude 또는 ChatGPT)가 실제로 처리한
순서 그대로 읽힙니다.

## 파괴적 작업 확인

되돌릴 수 없는 작업은 먼저 확인을 구합니다. `panel_clear`(모든 노드 삭제)와
`panel_restart_comfyui`는 예/아니오 카드를 띄우고 **예**를 눌러야만 실행됩니다 —
에이전트가 그래프를 조용히 날려버리거나 ComfyUI를 재시작할 수 없습니다.

## 재연결 내구성

멈춰버린(wedged) 오케스트레이터가 더 이상 패널을 고립시키지 않습니다. 이전
오케스트레이터가 여전히 브리지 포트를 붙잡고 있어도, **연결**을 누르면 실패하는
대신 그 좀비 프로세스를 회수합니다 — 막히는 대신 패널이 다시 연결됩니다.

## 입력창 첨부 파일

입력창에 첨부하거나, 끌어다 놓거나, 붙여넣을 수 있습니다. 이미지뿐 아니라 입력창은
이제 **동영상**, **워크플로우 `.json`**, **텍스트** 파일도 받아들이므로, 참고할
영상 클립이나 손볼 워크플로우, 메모 파일을 에이전트에게 바로 건넬 수 있습니다.

## 에이전트 답변 속 풍부한 미디어

실행 결과 미디어가 에이전트에게 다시 전달될 때, 출력은 단순한 이미지 블록이 아니라
에이전트가 추론할 수 있는 **메타데이터**를 함께 담고 있습니다: 각 출력의 경로
(하위 폴더 기준 상대 경로), 파일 크기, 픽셀 크기, 그리고 **에셋 세트 묶음** 정보
(이번 실행에서 나온 "N개 중 K번째 출력"과 형제 파일명들, 또는 "단일 출력"), 여기에
렌더링 소요 시간과 완료 시각까지 포함됩니다. 동영상 스토리보드는 페이로드에 포맷과
실제 프레임 수/fps가 담겨 있으면 이를 함께 추가합니다. 그 덕분에 에이전트는 실제로
저장된 결과물을 정확히 지칭하고, 크기·해상도·이번 실행에서 생성된 파일 개수까지
이야기할 수 있습니다.

## 코드 블록 복사 및 줄바꿈

렌더링된 코드 블록에는 마우스를 올리면 나타나는 **복사** 버튼과, 전역으로 저장되는
**줄바꿈** 토글이 있습니다(기본값은 꺼짐 — 켜기 전까지 긴 줄은 가로로 스크롤됩니다).
인라인 코드에도 각자 복사 버튼이 있습니다. 둘 다 패널 디자인에 맞춘 스타일을
사용합니다.

## 렌더 정체 경고

오케스트레이터는 ComfyUI 대기열을 수동적으로 감시하는 워치독을 실행합니다:
노드/진행률이 더 이상 나아가지 않는 렌더는 **정체됨**으로 표시되고 에이전트에게
알려집니다(그래서 막힌 작업 뒤에 무작정 작업을 계속 쌓지 않습니다). 임계값은
**설정 → Comfy MCP 에이전트 → 일반**의 **렌더 정체 경고 (초)** 설정입니다(기본값
180초, 범위 15–3600). 이 값은 연결 시점에 전송되고 **실시간으로** 반영되므로 — 값을
바꿔도 다시 연결할 필요가 없습니다. 자세한 내용은
[설정 → `COMFYUI_MCP_STALL_S`](/docs/configuration#panel-orchestrator--the-bridge)를
참고하세요.

## 백그라운드 탭 안정성

ComfyUI 탭이 **백그라운드**에 있어도 스트리밍 답변이 이제 정상적으로 렌더링됩니다.
이전에는 답변의 타자기 효과가 `requestAnimationFrame`으로 동작했는데, 브라우저는
숨겨진 탭에서 이를 멈추기 때문에 — 여러 단계로 이어지는 긴 실행 도중 탭을 전환하면
말풍선이 비어 있는 채로 스트리밍 커서만 멈춰 있어, 턴이 이미 끝났는데도 에이전트가
"생각하다 멈춘" 것처럼 보였습니다. 이제 탭이 숨겨지면 답변이 즉시 동기적으로
마무리되며, `visibilitychange` 핸들러가 탭이 숨겨질 때 대기 중인 답변을 모두
내보내고 탭으로 돌아오면 타자기 효과를 다시 시작합니다. 전면(foreground)에서의
애니메이션은 그대로입니다.

## RunPod 클라우드 제어

툴바의 **호스트 표시**에는 **🟢 로컬 · 사용자의 장비** 또는 **🔵 RunPod · `<pod>` ·
GPU · $/hr**이 표시되며, 클릭하면 **RunPod 제어판**이 열립니다: 실시간 상태 카드
(GPU / VRAM / 가동 시간 / $·hr / ComfyUI URL / 유휴 자동 정지 카운트다운), 파드를
**이름으로** 나열하는 드롭다운, 연결 / 시작 / 정지 / **로컬 사용**, 그리고 확인이
필요한 **배포** 버튼이 있습니다. API 키 카드에서 `RUNPOD_API_KEY`를 한 번만 설정해
두면 RunPod 콘솔을 건드리지 않고도 배포·모니터링·로컬⇄파드 전환·클라우드 GPU
정지까지 할 수 있습니다 — 호스트 표시는 항상 다음 렌더가 어디서 실행될지
알려줍니다. 자세한 내용은 [클라우드 배포](/docs/cloud-deployment)와 블로그 글
[임대한 클라우드 GPU에서 ComfyUI 실행하기](/docs/blog/runpod-comfyui)를 참고하세요.

## CivitAI 브라우저

툴바의 **Civitai** 버튼을 누르면 CivitAI 브라우저 전체가 열립니다 — 이미지, 동영상,
체크포인트, LoRA, 워크플로우를 검색·필터링하고 전체 화면 뷰어로 볼 수 있습니다.
결과를 골라 **에이전트와 공유**하거나, **컴퓨터로 다운로드**하거나, **포함된
워크플로우를 캔버스에 저장**할 수 있습니다. 자세한 이야기:
[ComfyUI 속 CivitAI](/docs/blog/civitai-in-comfyui).
