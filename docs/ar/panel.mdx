<Note>
  **متوفّرة الآن على Comfy Registry.** ثبّت **ComfyUI Agent Panel**
  (`comfyui-agent-panel`) من ComfyUI-Manager، أو ثبّتها من git للحصول على أحدث
  نسخة (راجع [الإعداد](#الإعداد) أدناه).
</Note>

**[comfyui-mcp-panel](https://github.com/artokun/comfyui-mcp-panel)** يضع وكيلًا
مستقلًا في الشريط الجانبي لـ ComfyUI. اطلب منه صورة أو سير عمل أو تعديلًا — فيعمل
على ComfyUI لديك ويردّ عليك في المكان نفسه. اختر مزوّدًا — **Claude** أو
**ChatGPT** أو **Gemini** أو **Ollama (محلي)** — فيعمل الوكيل المطابق له في
الخلفية: الاشتراكات **بلا مفتاح API**، والنماذج المحلية **بلا حساب أصلًا** (كما
تصل خلفية Ollama إلى أي نقطة وصول مستضافة متوافقة مع OpenAI أيضًا). راجع
[الخلفيات](/docs/backends) للاطّلاع على المصفوفة، و[حلبة النماذج اللغوية](/docs/arena)
لمعرفة الأداء الفعلي لكل فئة من النماذج.

```
you ⇄ panel (pick a provider) ⇄ loopback bridge ⇄ panel orchestrator ⇄ background agent: Claude · ChatGPT · Gemini · any LLM
```

**بلا مفاتيح API وبلا فوترة على كل رمز** لدى مزوّدي الاشتراكات — ومجانية تمامًا
وتعمل دون اتصال على النماذج المحلية. يستوثق الوكيل ببيانات تسجيل دخولك المخزّنة
على القرص (أو، في حالة Ollama، يتحدّث ببساطة إلى الخدمة المحلية). ومنسّق واحد على
منفذ جسر استرجاع محلي واحد (`ws://127.0.0.1:9199`) يخدم كل المزوّدين؛ ويختار كل
تبويب من تبويبات اللوحة مزوّده أثناء المصافحة. والجسر مقصور على الاسترجاع المحلي،
واللوحة تنفّذ **قائمة سماح ثابتة** من أوامر المخطط (لا شيفرة JavaScript عشوائية).

<Note>
  جديد هنا؟ [الخلفيات / المزوّدون](/docs/backends) يشرح أداة الاختيار، ومنفذ
  `AgentBackend` المحايد تجاه المزوّد، ومصفوفة القدرات (ما هو متطابق بين Claude
  وChatGPT، والفروق القليلة بينهما).
</Note>

## الإعداد

1. **ثبّت الحزمة** — ابحث عن `comfyui-agent-panel` في ComfyUI-Manager، أو من git:

   ```bash
   cd ComfyUI/custom_nodes
   git clone https://github.com/artokun/comfyui-mcp-panel
   ```

   <Warning>
   **اختر `Latest` لا `Nightly` من قائمة الإصدارات المنسدلة في Manager.** رغم
   الاسم، فإن **Nightly** في Manager لا يُبنى ليليًا: فهو يستنسخ المستودع **مرة
   واحدة** وقت التثبيت ثم لا يتتبّع الفرع بعدها أبدًا. إنه يجمّدك عند أي إيداع
   صادف أن كان `main` في ذلك اليوم، بينما يواكب `Latest` كل إصدار — لذا فإن
   Nightly *أقدم* من Latest في المعتاد، ويزداد تخلّفه بصمت كلما طالت مدة تركه.
   وهو لا يبلّغ عن توفّر أي تحديث، لأنه من وجهة نظره لا يوجد تحديث.

   ولمعرفة موضعك الفعلي، قارن قيمة SHA تحت **Node Pack Info → Version** بـ[سجل
   إيداعات المستودع](https://github.com/artokun/comfyui-mcp-panel/commits/main).
   وللخروج من ذلك، إما أن تختار `Latest (x.y.z)` من القائمة نفسها، أو — إن أردت
   البقاء على git — أن تنفّذ `git pull` في `custom_nodes/comfyui-mcp-panel`،
   فيتقدّم بسلاسة.
   </Warning>

2. **سجّل الدخول إلى المزوّد الذي تريده** مرة واحدة، حتى يستطيع الوكيل العامل في
   الخلفية استخدام اشتراكك:

   ```bash
   claude        # Claude — or: claude setup-token
   codex login   # ChatGPT (Codex)
   ```

3. **شغّل المنسّق** على جهازك واتركه يعمل — راجع
   [تشغيل منسّق اللوحة](/docs/ar/installation#3-تشغيل-منسّق-اللوحة):

   ```bash
   npx -y comfyui-mcp@latest connect
   ```

4. **أعد تشغيل ComfyUI**، وافتح تبويب **Agent**، و**اختر مزوّدًا** (شريحتا Claude /
   ChatGPT)، ثم انقر **اتصال**. ترتبط اللوحة بجسر الاسترجاع المحلي للمنسّق. اكتب
   طلبًا فيردّ الوكيل. و**قطع الاتصال** يفكّ الارتباط؛ ويظل المنسّق يعمل حتى توقفه.

لا حاجة إلى `claude mcp add`، ولا إلى مفتاح API. فاللوحة امتداد واجهة أمامية محض
ولا تستطيع تشغيل المنسّق بنفسها، لذا فهو دائمًا عملية تبدؤها أنت — واللوحة تتصل
تلقائيًا بجسر يعمل مسبقًا. والمتطلبات المسبقة هي وجود Node.js/`npx` في مسار
PATH لديك، وتسجيل الدخول إلى المزوّد كما سبق. غيّر منفذ الجسر عبر
`COMFYUI_MCP_BRIDGE_PORT`.

<Note>
**هل تقود ComfyUI بعيدًا** (وحدة GPU سحابية، أو جهازًا آخر على شبكتك المحلية)؟ ما
يزال الإعداد أعلاه ساريًا، لكن شغّل المنسّق **على جهازك أنت**، لا على الجهاز
البعيد: فأمر `npx -y comfyui-mcp@latest connect <remote-url>` يتكفّل بالباقي، بما
في ذلك نفق آمن يعود إلى صفحة HTTPS الخاصة بالـ Pod. ثم انقر «اتصال» في اللوحة.
راجع [النشر السحابي](/docs/cloud-deployment) للشرح الكامل.
</Note>

<Note>
  **تهيئة المزوّد.** عند الاتصال تتحقّق اللوحة من جاهزية كل مزوّد (وجود واجهة سطر
  الأوامر الخاصة به في PATH لديك + تسجيل دخول على القرص؛ وسلسلة مفاتيح macOS
  مُعالَجة). ولا تظهر بطاقة التهيئة إلا حين **لا يكون أي** من المزوّدَين مسجَّل
  الدخول. وإذا كان اختيارك المحفوظ غير صالح للاستخدام فإن اللوحة **تنتقل تلقائيًا
  إلى مزوّد جاهز** (مع الاحتفاظ بتفضيلك المحفوظ)، ويعرض صفّ المزوّد غير الجاهز
  إجراء **«الإعداد»** الذي يمهّد لخطوة `claude` / `codex login` التي تُنفَّذ مرة
  واحدة. راجع [الخلفيات ← الجاهزية والتهيئة](/docs/backends#connect-time-readiness--onboarding).
</Note>

## ما الذي يستطيع فعله

يحمّل الوكيل (Claude *أو* ChatGPT) مهارات النماذج الخاصة بـ comfyui-mcp
(IDEOGRAM وWAN وLTX وQwen وغيرها)، فيعرف مسبقًا النماذج التي تشغّلها — يعرفها
Claude أصليًا، ويعرفها ChatGPT عبر المعرفة نفسها معروضةً كأدوات MCP
([تكافؤ المعرفة](/docs/tools/skills-knowledge)). ويستطيع توليد الصور والفيديو
والصوت، وفحص ComfyUI لديك وإدارته، والاستدلال حول إعدادك — ثم الرد في محادثة
اللوحة.

كما يستطيع **تحميل سير عمل كامل أو حزمة تثبيت دفعة واحدة**
(`panel_load_workflow pack:<name>`)، وهو **واعٍ بالتكلفة**: فالحزم المرفقة تعمل
على GPU محلي ومجانًا، وفي حالة المخطط المرتجل يفحص الوكيل بيئة التشغيل
(`list_packs` مع `action:"check_runtime"`) و**يسأل قبل إنفاق أرصدة API المدفوعة**.
راجع [المهارات والحزم وتكلفة التشغيل](/docs/tools/skills-knowledge).

## قيادة المخطط الحيّ

يعمل الوكيل المستقل على ComfyUI الحيّ لديك عبر **قائمة سماح ثابتة** من أوامر
`panel_*` — بلا شيفرة JavaScript عشوائية. وتمرّ كل تعديلات المخطط عبر تتبّع
التغييرات في LiteGraph، فيمكن التراجع عن كل تعديل بـ **Ctrl+Z**. وسطح `panel_*`
نفسه معروض بصورة متطابقة على الخلفيتين (داخل العملية نفسها لـ Claude، وعبر MCP
على HTTP استرجاعي لـ ChatGPT/Codex)، فيكون [التكافؤ](/docs/backends) تلقائيًا.

### القراءة

| الأداة | الأثر |
|---|---|
| `panel_query_graph` | استعلم عن المخطط المعروض — تصفية/اجتياز/تجميع، ضمن حدّ للرموز |
| `panel_get_subgraph` | اقرأ المخطط الداخلي لعقدة مخطط فرعي |
| `panel_view_selected` | اقرأ العقدة (أو العقد) التي **حدّدها** المستخدم — يجيب عن «هذه العقدة» في استدعاء واحد |
| `panel_view_nodes_in_viewport` | اقرأ ما هو **ظاهر على الشاشة** فقط (مستطيل منفذ العرض + التكبير) — يحصر العمل في مخطط كبير |
| `panel_get_errors` | **لماذا** صارت العقدة حمراء — كل عقدة بها خطأ مقرونةً بسببه (نموذج مفقود + رابط تنزيله، وسائط مفقودة، تحقّق، `exception_type` في وقت التشغيل) |
| `panel_list_workflows` | اسرد تبويبات سير العمل المفتوحة وأيّها النشط |
| `panel_list_nodes` | اسرد حزم العقد المخصّصة المثبَّتة |
| `panel_list_mcp` | اسرد خوادم MCP المتصلة |
| `panel_get_content_mode` | اقرأ حالة الموافقة على محتوى البالغين (NSFW) |

### تعديل المخطط (قابل للتراجع)

| الأداة | الأثر |
|---|---|
| `panel_add_node` | أضف عقدة حسب class_type |
| `panel_remove_node` | أزل عقدة |
| `panel_connect` / `panel_disconnect` | صِل / افصل المنافذ بالاسم أو بالفهرس (احذف كلا المنفذين في `panel_connect` للمطابقة التلقائية حسب النوع؛ و`auto_match:false` يعيد دلالة الفهرس 0 القديمة) |
| `panel_set_widget` | غيّر قيمة عنصر تحكّم (steps، cfg، الموجّهات، …) |
| `panel_edit_node` | حرّك عقدة أو أكثر أو غيّر حجمها أو أعد تسميتها أو لوّنها أو أعد تشكيلها أو اطوِها أو ثبّتها، في عملية ذرّية واحدة |
| `panel_auto_layout` | رتّب المخطط كله (أو جزءًا منه) تلقائيًا في تخطيط تدفّق/شبكة نظيف بحسب طوبولوجيا الوصلات — استخدم `dry_run` للمعاينة |
| `panel_clear` | أزل كل العقد — والمسح بأكمله يُتراجَع عنه بـ Ctrl+Z واحد |

### المخططات الفرعية

| الأداة | الأثر |
|---|---|
| `panel_select_nodes` | حدّد عقدًا على لوحة الرسم (تحديد متعدّد) |
| `panel_create_subgraph` | اجمع العقد المحدّدة في مخطط فرعي («Convert to Subgraph») |
| `panel_enter_subgraph` | ادخل إلى مخطط فرعي لقراءة عقده الداخلية أو تحريرها |
| `panel_exit_subgraph` | ارجع إلى المخطط الأب / الجذر |

### التخطيط المكاني

يستطيع الوكيل رؤية هندسة العقد — إذ تُرجع صفوف التفاصيل في `panel_query_graph`
قيمتَي `pos`/`size` لكل عقدة، إضافةً إلى `rails` مداخل ومخارج المخططات الفرعية،
و`groups`، و`color`/`collapsed` لكل عقدة — ويرتّب لوحة الرسم بمجموعة مقابلة من
عمليات الكتابة، ثم **يلتقط صورة للشاشة** ليحكم على تخطيطه بنفسه. وتربط مهارة
`workflow-layout` هذه الأدوات في تخطيط تلقائي مُطبَّق على طبقات الاعتماديات
وخالٍ من التداخل، قاعدته الأبرز *أبقِ المداخل والمخارج مكشوفة دائمًا* حتى تستطيع
الانطلاق مباشرة.

| الأداة | الأثر |
|---|---|
| `panel_move_rail` | انقل شريط مداخل/مخارج مخطط فرعي لتبقى الوصلات الحدودية قصيرة |
| `panel_create_group` / `panel_move_group` / `panel_edit_group` / `panel_remove_group` | أنشئ إطار مجموعة معنونًا أو انقله أو أعد تسميته/تلوينه أو احذفه (مرّر `node_ids` للالتفاف التلقائي) |
| `panel_screenshot` | اعرض لوحة الرسم في صورة PNG وأعدها كصورة ليتحقّق الوكيل من تخطيطه |

### تبويبات سير العمل

| الأداة | الأثر |
|---|---|
| `panel_new_workflow` | افتح سير عمل جديدًا فارغًا في تبويب جديد (ولا يمسح الحالي أبدًا) |
| `panel_open_workflow` | انتقل إلى سير عمل بالمسار أو باسم الملف |
| `panel_rename_workflow` | أعد تسمية سير عمل |
| `panel_close_workflow` | أغلق تبويبًا (يرفض إغلاقه مع تغييرات غير محفوظة ما لم يُجبَر) |
| `panel_save_workflow` | احفظ أو احفظ باسم برمجيًا — دون ظهور أي مربع حوار |

### تحميل سير عمل دفعة واحدة

| الأداة | الأثر |
|---|---|
| `panel_load_workflow` | استبدل المخطط الحيّ بسير عمل كامل في استدعاء واحد — ويُفضَّل استخدام `pack:<name>` لتحميل سير عمل حزمة تثبيت مرفقة يعمل على GPU محلي، دون تمرير ملف JSON عبر المحادثة. ويصير المخطط المستبدَل نقطة تراجع (ضغط Esc مرتين / `/revert`). |

### المعرفة والوعي بالتكلفة

يكتشف الوكيل الخبرة المرفقة ويفحص تكلفة التشغيل قبل إنفاق الأرصدة (الأدوات نفسها
على الخلفيتين — راجع
[المهارات والحزم وتكلفة التشغيل](/docs/tools/skills-knowledge)):

| الأداة | الأثر |
|---|---|
| `list_packs` (`action:"skill_list"` / `action:"skill_read"`) | اكتشف واقرأ مهارات عائلات النماذج ومهارات سير العمل المرفقة |
| `list_packs` (`action:"list"` / `action:"read_workflow"`) | اسرد حزم التثبيت بأمر واحد (GPU محلي / مجانية) واقرأ مخطط حزمة |
| `list_packs` (`action:"list_templates"`) | اسرد قوالب سير العمل الرسمية لـ ComfyUI على الخادم المتصل |
| `list_packs` (`action:"check_runtime"`) | صنّف المخطط بأنه **محلي** (مجاني) أو **api/mixed/unknown** (مدفوع) — فيسأل الوكيل قبل إنفاق أرصدة API المدفوعة |

| الأداة | الأثر |

|---|---|

</Note>

## الإرجاع والاسترجاع

الرسائل السابقة ليست مجمّدة. مرّر المؤشر فوق أي رسالة، فيفتح زر **✎ التحرير**
نافذة استرجاع: استرجع **الشيفرة** (أعد المخطط إلى لقطة ذلك الدور)، أو
**المحادثة** (فرّع الجلسة رجوعًا إلى تلك النقطة)، أو **كليهما**، ثم أعد إرسال
رسالة معدَّلة من هناك. وتعتمد استعادة المخطط على لقطات لكل دور، فالتراجع عن دور
يعيد المخطط تمامًا إلى ما بدأ منه.

اختصاران يغطّيان الحالتين الشائعتين:

- **`/revert`** — تراجع عن تعديلات المخطط في الدور الأخير.
- **ضغط Esc مرتين** — إرجاع سريع للدور الأخير: يستعيد المخطط ويعيد الرسالة إلى
  مربع الكتابة لتحريرها وإرسالها من جديد.

<Note>
  استرجاع **الشيفرة** (المخطط) يعمل على **كلتا** الخلفيتين — فهو موجود في المنسّق
  عبر لقطات لكل دور. أما استرجاع **المحادثة** (تفريع الدردشة رجوعًا إلى دور سابق)
  فمتاح **لـ Claude فقط** حاليًا؛ إذ لا تستأنف خلفية ChatGPT/Codex إلا خيوط
  المحادثة كاملة، فتحجب اللوحة ذلك النطاق عنها. راجع
  [مصفوفة القدرات](/docs/backends#capability-matrix).
</Note>

## لوحة الرسائل المعلّقة

اكتب بينما الوكيل مشغول ولن تضيع رسالتك في المحادثة — بل تنتظر في لوحة
**المعلّقة** الثابتة المرسّاة فوق لوحة التنزيلات، خارج تدفّق المحادثة. ولكل رسالة
معلّقة أزرار **تحرير** و**إرسال الآن** و**حذف**، ومقبض سحب (≡، على اليسار)
لـ**إعادة ترتيب** الطريقة التي يصرّفها بها الوكيل. و**إرسال الآن** يقاطع الدور
الحالي لتوجيهه فورًا. وحين تُسحب رسالة معلّقة من الطابور تظهر في **أسفل**
المحادثة، فيُقرأ السجل بالترتيب الذي عالجها به الوكيل (Claude أو ChatGPT) تمامًا.

## تأكيد العمليات المدمِّرة

الإجراءات التي لا رجعة فيها تسأل أولًا. فـ`panel_clear` (مسح كل العقد)
و`panel_restart_comfyui` يعرضان بطاقة نعم / لا ولا يتصرّفان إلا عند **نعم** — فلا
يستطيع الوكيل أن ينسف مخططك أو يعيد تشغيل ComfyUI بصمت.

## متانة إعادة الاتصال

لم يعد المنسّق المتعثّر يترك اللوحة عالقة. فإن كان منسّق سابق ما يزال محتجزًا
لمنفذ الجسر، فإن نقر **اتصال** يستعيد تلك النسخة الشبح بدل أن يفشل — فتعيد اللوحة
الاتصال بدل أن تتركك عالقًا.

## مرفقات مربع الكتابة

أرفِق أو أفلِت أو الصق في مربع الكتابة. وإلى جانب الصور، صار مربع الكتابة يقبل
ملفات **الفيديو** و**سير العمل `.json`** و**النصوص**، فيمكنك أن تسلّم الوكيل
مقطعًا مرجعيًا، أو سير عمل ليكيّفه، أو ملف ملاحظات مباشرة.

## الوسائط الغنية في ردود الوكيل

حين تُعاد وسائط عملية تشغيل إلى الوكيل، لا يكون الناتج مجرد كتلة صورة — بل يحمل
**بيانات وصفية** يستطيع الوكيل الاستدلال بها: مسار كل مخرَج (نسبةً إلى المجلد
الفرعي)، وحجم الملف، وأبعاده بالبكسل، و**تجميع مجموعة الأصول** («المخرَج K من N
في هذا التشغيل» مع أسماء ملفاته الشقيقة، أو «مخرَج وحيد»)، إضافةً إلى مدة التوليد
ووقت الانتهاء. وتضيف لوحات الفيديو القصصية الصيغة وعدد الإطارات الحقيقي ومعدّلها
حين تحملها الحمولة. فيسمّي الوكيل النتيجة المحفوظة فعليًا تسميةً دقيقة، ويستطيع
الحديث عن الحجم والأبعاد وعدد الملفات التي أنتجها التشغيل.

## نسخ كتل الشيفرة ولفّ أسطرها

تحصل كتل الشيفرة المعروضة على زر **نسخ** يظهر عند تمرير المؤشر، وعلى مفتاح
**لفّ الأسطر** عام ومحفوظ (معطّل افتراضيًا — تتمرّر الأسطر الطويلة أفقيًا حتى
تفعّله). وللشيفرة السطرية زر نسخ خاص بها. وكلاهما مُنسَّق ليطابق اللوحة.

## تحذير تعثّر التوليد

يشغّل المنسّق مراقبًا سلبيًا على قائمة انتظار ComfyUI لديك: فأي عملية توليد يتوقّف
تقدّمها أو عقدتها عن التحرّك تُعلَّم بأنها **متعثّرة** ويُبلَّغ الوكيل بذلك (حتى
يكفّ عن تكديس المهام عميانًا خلف مهمة متعثّرة). والعتبة هي إعداد
**تحذير تعثّر التوليد (بالثواني)** ضمن **الإعدادات → Comfy MCP Agent → عام**
(الافتراضي 180 ثانية، والمدى 15–3600). ويُرسَل عند الاتصال ويُدفَع **حيًّا** —
فتغييره يُطبَّق دون إعادة اتصال. راجع
[الإعدادات ← `COMFYUI_MCP_STALL_S`](/docs/configuration#panel-orchestrator--the-bridge).

## الموثوقية في التبويبات الخلفية

صارت الردود المتدفّقة تُعرض حتى حين يكون تبويب ComfyUI في **الخلفية**. فقد كانت
آلة كتابة الرد تعمل سابقًا على `requestAnimationFrame`، وهو ما يوقفه المتصفح في
تبويب مخفي — فكان الانتقال إلى تبويب آخر أثناء تشغيل طويل متعدّد المراحل يترك
الفقاعة فارغة مع مؤشّر تدفّق عالق، وكأن الوكيل «عالق في التفكير» رغم انتهاء
الدور. أما الآن فيُنهى الرد تزامنيًا حين يُخفى التبويب، ويقوم معالج
`visibilitychange` بتصريف أي رد معلّق عند الإخفاء واستئناف آلة الكتابة عند
العودة. ولم يتغيّر التحريك في المقدّمة.

## التحكم السحابي عبر RunPod

تعرض **شريحة المضيف** في شريط الأدوات **🟢 محلي · جهازك** أو **🔵 RunPod · `<pod>` ·
GPU · $/hr** وتفتح **لوحة تحكم RunPod**: بطاقة حالة حيّة (GPU / VRAM / مدة التشغيل
/ $·hr / رابط ComfyUI / العدّ التنازلي للإيقاف التلقائي عند الخمول)، وقائمة منسدلة
تسرد الـ Pods لديك **بالاسم**، وأزرار اتصال / تشغيل / إيقاف / **استخدام المحلي**،
و**نشر** مسلّح بتأكيد. اضبط `RUNPOD_API_KEY` مرة واحدة في بطاقة مفاتيح API
وستتمكّن من النشر والمراقبة والتبديل بين المحلي والـ Pod وإيقاف وحدة GPU سحابية
دون لمس وحدة تحكم RunPod — وشريحة المضيف تخبرك دائمًا أين ستُنفَّذ عملية التوليد
التالية. راجع [النشر السحابي](/docs/cloud-deployment) والمدوّنة
[شغّل ComfyUI على وحدة GPU سحابية مستأجرة](/docs/blog/runpod-comfyui).

## متصفّح CivitAI

يفتح زر **Civitai** في شريط الأدوات متصفّح CivitAI كاملًا — صور وفيديوهات وملفات
checkpoint وLoRA ومسارات سير عمل، مع بحث وعوامل تصفية وعارض ملء الشاشة. اختر نتيجة
لـ**مشاركتها مع الوكيل**، أو **تنزيلها إلى جهازك**، أو **حفظ سير عمل مضمّن** على
لوحة الرسم. والقصة كاملة في
[CivitAI داخل ComfyUI](/docs/blog/civitai-in-comfyui).
