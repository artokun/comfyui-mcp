## 2. Добавление MCP-сервера

ComfyUI MCP публикуется в npm как `comfyui-mcp` и запускается через `npx` — глобальная установка не нужна.

<Tabs>
  <Tab title="Локальный ComfyUI">
    Сервер сам определяет локальную установку и её порт. Добавьте его в `~/.claude/settings.json`:

    ```json
    {
      "mcpServers": {
        "comfyui": {
          "command": "npx",
          "args": ["-y", "comfyui-mcp"]
        }
      }
    }
    ```
  </Tab>
  <Tab title="Удалённый ComfyUI">
    Укажите любой доступный экземпляр через `--comfyui-url`. Для инструментов, работающих по
    HTTP (генерация, очередь, воркфлоу, поиск моделей и т. д.), локальная установка не нужна.
    Если хост не является loopback-адресом, сервер переходит в **удалённый режим** и пропускает
    автоопределение `COMFYUI_PATH`, чтобы устаревшая локальная установка не могла незаметно
    перехватить загружаемые файлы.

    ```json
    {
      "mcpServers": {
        "comfyui": {
          "command": "npx",
          "args": ["-y", "comfyui-mcp", "--comfyui-url", "https://my-comfy.example.com"]
        }
      }
    }
    ```

    <Note>
      Большинство инструментов прекрасно работают с удалённым ComfyUI — включая установку
      кастомных узлов через HTTP API ComfyUI-Manager. Путь к локальной установке по-настоящему
      нужен только для установки самого ComfyUI, операций на базе comfy-cli, чтения логов и
      удаления файлов моделей; в удалённом режиме они возвращают понятную ошибку.
      См. [Как это работает](/docs/concepts).
    </Note>
  </Tab>
  <Tab title="Comfy Cloud">
    Задайте `COMFYUI_API_KEY`, чтобы работать с [Comfy Cloud](https://cloud.comfy.org). Сервер
    переходит в **облачный режим**: HTTP-примитивы идут через `cloud.comfy.org` с
    аутентификацией по `X-API-Key`. Инструменты, завязанные на WebSocket, а также на локальную
    файловую систему и процессы, выбрасывают понятную ошибку `CLOUD_UNSUPPORTED`.

    ```json
    {
      "mcpServers": {
        "comfyui": {
          "command": "npx",
          "args": ["-y", "comfyui-mcp"],
          "env": {
            "COMFYUI_API_KEY": "your-comfy-cloud-api-key"
          }
        }
      }
    }
    ```

    <Note>
      Облачный режим пропускает автоопределение локального `COMFYUI_PATH` и использует
      собственную библиотеку моделей облака. Инструменты, которым нужен локальный процесс или
      файловая система, выбрасывают `CLOUD_UNSUPPORTED`; остальные не падают, а работают в
      урезанном виде — `list_local_models` возвращает пустой список, а `apply_manifest`
      сообщает `skipped`/`failed` по каждому элементу вместо того, чтобы завершиться ошибкой
      целиком. Полная матрица соответствия возможностей — на странице
      [Конфигурация](/docs/configuration#deployment-modes).
    </Note>
    <Note>
      **Только облако?** [Comfy Cloud MCP от Comfy-Org](https://docs.comfy.org/agent-tools) (публичная бета) — канонический выбор, см. [Локально vs. Comfy Cloud](/docs/local-vs-comfy-cloud). Облачный режим `comfyui-mcp` пригодится, если вам нужен один MCP сразу для локального / удалённого / облачного варианта или поддержка облака нужна уже сегодня.
    </Note>
  </Tab>
  <Tab title="Управляемый / корпоративный Claude Code">
    В Claude Code, которым управляет организация, нет CLI `claude`, чтобы выполнить
    `claude mcp add`, а список **Управляемые MCP-серверы** контролируется администратором: он
    успешно проверит сервер, а потом откажется его сохранить. **Настройки разработчика →
    Изменить конфигурацию** открывает `claude_desktop_config.json`, который вкладка Code вообще
    не читает. Рабочих путей два.

    **Вариант A — HTTP.** Запустите сервер сами и добавьте его как *удалённый* коннектор:

    ```bash
    npx -y comfyui-mcp@latest --http
    ```

    Это поднимает streamable-HTTP на `http://127.0.0.1:9100/mcp` — адрес привязки меняется через
    `--host` / `--port`. Добавьте этот URL как удалённый коннектор, транспорт HTTP, без
    аутентификации. Процесс должен работать всё время, пока вы пользуетесь инструментами, а
    управляемый список организации всё равно может отказаться сохранить запись — тогда
    переходите к варианту B.

    **Вариант B — stdio из вашего пользовательского конфига.** Claude запускает сервер сам, так
    что ничего держать запущенным не нужно. Установите пакет глобально **при полностью закрытом
    Claude Code**, иначе Windows удержит файлы открытыми и оставит наполовину удалённый пакет,
    который `npm ls -g` показывает без версии:

    ```bash
    npm install -g comfyui-mcp
    npm root -g
    ```

    Затем добавьте блок `mcpServers` **на верхнем уровне** `~/.claude.json` — в Windows это
    `C:\Users\ВАШЕ_ИМЯ\.claude.json` — указав `node` на путь, который напечатал `npm root -g`:

    ```json
    {
      "mcpServers": {
        "comfyui": {
          "command": "node",
          "args": ["C:/Users/YOUR_NAME/AppData/Roaming/npm/node_modules/comfyui-mcp/dist/index.js"]
        }
      }
    }
    ```

    После этого перезапустите Claude Code **полностью, включая значок в системном трее** —
    иначе конфигурация не будет прочитана заново.

    <Note>
      **Проверьте, спросив у агента, какие у него есть инструменты.** В управляемой сборке ни
      один элемент интерфейса не отражает работающий MCP-сервер надёжно, так что функциональная
      проверка — единственная, которая не врёт.
    </Note>
    <Note>
      Названия пунктов меню и пути на стороне Claude выше наблюдались на одной управляемой
      сборке — воспринимайте их как ориентир, а не как точные подписи. Держите HTTP-эндпоинт на
      loopback: если привязать его к не-loopback хосту, сервер откажется стартовать, пока вы не
      зададите общий секрет через `--token`. См. [Удалённый коннектор](/docs/remote-connector).
    </Note>
  </Tab>
</Tabs>

После этого выполните `/mcp` в Claude Code, чтобы подключиться.

## 3. Запуск оркестратора панели

Нужно только для **панели в боковом меню**. Пропустите этот шаг, если управляете ComfyUI из
Claude Code или другого MCP-клиента — там используется настроенный выше MCP-сервер.

Панель — это чисто фронтендовое расширение ComfyUI: оно не может запустить процесс на вашей
машине, поэтому **оркестратор вы запускаете сами**, а панель подключается к нему.

```bash
npx -y comfyui-mcp@latest connect
```

Это сокращение для `--panel-orchestrator`. Команда автоматически нацеливается на тот ComfyUI,
который открыт в браузере, поднимает мост на `ws://127.0.0.1:9199` (переопределяется через
`COMFYUI_MCP_BRIDGE_PORT`) и должна оставаться запущенной, пока вы пользуетесь панелью. Затем
откройте вкладку **Агент**, выберите провайдера и нажмите **Подключить**.

Управляете **удалённым** ComfyUI — облачным подом или другой машиной в локальной сети?
Запустите ту же команду на **своей машине**, а не на удалённой, и передайте URL:

```bash
npx -y comfyui-mcp@latest connect https://your-pod-url
```

Вход у провайдера и сам агент остаются локальными; на удалённый хост ничего не
устанавливается. Подробности про туннель — в разделе
[Развёртывание в облаке](/docs/cloud-deployment).

## 4. (Необязательно) Токены

Некоторые инструменты используют API-токены. Задайте их в блоке `env` сервера (см. [Конфигурация](/docs/configuration)):

- `CIVITAI_API_TOKEN` — скачивание с CivitAI, требующее авторизации
- `HUGGINGFACE_TOKEN` — более высокие лимиты запросов к HuggingFace
- `GITHUB_TOKEN` — генерация скиллов / получение метаданных узлов
- `COMFY_API_KEY` — хостируемые API-узлы comfy.org

## Локальная разработка

Проект использует `npm link`, поэтому `npx comfyui-mcp` указывает на вашу локальную сборку:

```bash
git clone https://github.com/artokun/comfyui-mcp
cd comfyui-mcp
npm install
npm run build
npm link
```

После изменений в коде: `npm run build`, затем `/mcp`, чтобы переподключиться.
