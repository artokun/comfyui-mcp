<Note>
  **حالا روی Comfy Registry.** **ComfyUI Agent Panel**
  (`comfyui-agent-panel`) را از ComfyUI-Manager نصب کنید، یا برای تازه‌ترین نسخه
  از git نصب کنید (پایین‌تر [برپاسازی](#برپاسازی) را ببینید).
</Note>

**[comfyui-mcp-panel](https://github.com/artokun/comfyui-mcp-panel)** یک عامل
خودگردان را در نوار کناری ComfyUI می‌نشاند. از آن تصویری، گردش‌کاری یا تغییری
بخواهید — روی ComfyUI خودتان کار می‌کند و همان‌جا پاسخ می‌دهد. یک سرویس‌دهنده
انتخاب کنید — **Claude**، **ChatGPT**، **Gemini** یا **Ollama (محلی)** — و عامل
متناظرش در پس‌زمینه اجرا می‌شود: اشتراک‌ها **بدون کلید API**، مدل‌های محلی
**بدون هیچ حسابی** (و بک‌اند Ollama به هر نقطهٔ اتصال میزبانی‌شدهٔ سازگار با
OpenAI هم می‌رسد). برای دیدن ماتریس، [بک‌اندها](/docs/backends) را ببینید و برای
اینکه هر ردهٔ مدل واقعاً چطور عمل می‌کند، [میدان مدل‌های زبانی](/docs/arena) را.

```
you ⇄ panel (pick a provider) ⇄ loopback bridge ⇄ panel orchestrator ⇄ background agent: Claude · ChatGPT · Gemini · any LLM
```

روی سرویس‌دهنده‌های اشتراکی **نه کلید API لازم است و نه صورت‌حساب به‌ازای هر
توکن** — و روی مدل‌های محلی کاملاً رایگان/آفلاین است. عامل با ورودِ ذخیره‌شده روی
دیسک شما احراز هویت می‌کند (یا، در مورد Ollama، فقط با سرویس محلی حرف می‌زند). یک
ارکستریتور روی یک درگاه پل لوپ‌بک (`ws://127.0.0.1:9199`) به همهٔ سرویس‌دهنده‌ها
خدمت می‌دهد؛ هر زبانهٔ پنل سرویس‌دهنده‌اش را هنگام دست‌دادن انتخاب می‌کند. پل فقط
روی لوپ‌بک است، و پنل تنها یک **فهرست مجاز ثابت** از فرمان‌های گراف را اجرا
می‌کند (هیچ JavaScript دلخواهی).

<Note>
  تازه‌واردید؟ [بک‌اندها / سرویس‌دهنده‌ها](/docs/backends) انتخابگر، درگاه
  سرویس‌دهنده‌خنثای `AgentBackend` و ماتریس قابلیت‌ها را توضیح می‌دهد (آنچه میان
  Claude و ChatGPT یکسان است، و همان چند چیز اندکی که فرق می‌کند).
</Note>

## برپاسازی

1. **بسته را نصب کنید** — در ComfyUI-Manager عبارت `comfyui-agent-panel` را جست‌وجو کنید، یا از git:

   ```bash
   cd ComfyUI/custom_nodes
   git clone https://github.com/artokun/comfyui-mcp-panel
   ```

   <Warning>
   **در فهرست کشویی نسخه در Manager، `Latest` را انتخاب کنید، نه `Nightly`.**
   برخلاف نامش، **Nightly** در Manager هر شب ساخته نمی‌شود: مخزن را هنگام نصب
   **یک بار** کلون می‌کند و پس از آن دیگر هرگز شاخه را دنبال نمی‌کند. شما را روی
   همان کامیتی که آن روز `main` بوده منجمد می‌کند، در حالی که `Latest` با هر
   انتشار جلو می‌آید — بنابراین Nightly معمولاً *قدیمی‌تر* از Latest است و هرچه
   بیشتر رهایش کنید، بی‌سروصدا بیشتر عقب می‌ماند. گزارش می‌دهد به‌روزرسانی‌ای در
   دسترس نیست، چون از دید خودش واقعاً نیست.

   برای اینکه ببینید واقعاً کجا ایستاده‌اید، SHA زیر **Node Pack Info →
   Version** را با [تاریخچهٔ کامیت‌های
   مخزن](https://github.com/artokun/comfyui-mcp-panel/commits/main) مقایسه کنید.
   برای بیرون آمدن، یا در همان فهرست کشویی `Latest (x.y.z)` را انتخاب کنید، یا —
   اگر می‌خواهید روی git بمانید — در `custom_nodes/comfyui-mcp-panel` یک
   `git pull` بزنید که تمیز fast-forward می‌شود.
   </Warning>

2. **یک بار در سرویس‌دهنده‌ای که می‌خواهید وارد شوید**، تا عامل پس‌زمینه بتواند از
   اشتراک شما استفاده کند:

   ```bash
   claude        # Claude — or: claude setup-token
   codex login   # ChatGPT (Codex)
   ```

3. **ارکستریتور را روی دستگاه خودتان راه بیندازید** و باز نگهش دارید — به
   [راه‌اندازی ارکستریتور پنل](/docs/fa/installation#3-راهاندازی-ارکستریتور-پنل) نگاه کنید:

   ```bash
   npx -y comfyui-mcp@latest connect
   ```

4. **ComfyUI را دوباره راه‌اندازی کنید**، زبانهٔ **عامل** را باز کنید، **یک
   سرویس‌دهنده انتخاب کنید** (چیپ‌های Claude / ChatGPT) و **اتصال** را بزنید. پنل
   به پل لوپ‌بک ارکستریتور پیوند می‌خورد. درخواستی تایپ کنید و عامل پاسخ می‌دهد.
   **قطع اتصال** این پیوند را برمی‌دارد؛ ارکستریتور تا وقتی خودتان متوقفش نکنید
   در حال اجرا می‌ماند.

نه `claude mcp add` لازم است، نه کلید API. پنل یک افزونهٔ کاملاً فرانت‌اندی است و
نمی‌تواند خودش ارکستریتور را بالا بیاورد، پس ارکستریتور همیشه فرایندی است که شما
راه می‌اندازید — پنل خودکار به پلی وصل می‌شود که از قبل در حال اجراست. پیش‌نیازها
Node.js/`npx` روی PATH شما و همان ورودی است که بالا گفته شد. درگاه پل را با
`COMFYUI_MCP_BRIDGE_PORT` عوض کنید.

<Note>
**یک ComfyUI دوردست را هدایت می‌کنید؟** (یک پاد GPU ابری، دستگاهی دیگر روی شبکهٔ
محلی) برپاسازی بالا همچنان برقرار است، اما ارکستریتور را **روی دستگاه خودتان**
اجرا کنید، نه روی دستگاه دوردست: `npx -y comfyui-mcp@latest connect <remote-url>`
بقیه را انجام می‌دهد، از جمله یک تونل امن به صفحهٔ HTTPS پاد. بعد در پنل «اتصال»
را بزنید. برای شرح کامل [استقرار ابری](/docs/cloud-deployment) را ببینید.
</Note>

<Note>
  **آماده‌سازی سرویس‌دهنده.** هنگام اتصال، پنل آمادگی هر سرویس‌دهنده را بررسی
  می‌کند (بودن ابزار خط فرمانش روی PATH شما + یک ورود روی دیسک؛ Keychain مربوط به
  macOS هم پشتیبانی می‌شود). کارت آماده‌سازی فقط وقتی ظاهر می‌شود که در **هیچ‌کدام**
  از سرویس‌دهنده‌ها وارد نشده باشید. اگر انتخاب ذخیره‌شدهٔ شما قابل استفاده نباشد،
  پنل **خودکار به یک سرویس‌دهندهٔ آماده سوئیچ می‌کند** (ترجیح ذخیره‌شدهٔ شما حفظ
  می‌شود)، و ردیف سرویس‌دهندهٔ آماده‌نشده یک کنش **«برپاسازی»** پیش می‌گذارد که همان
  گام یک‌بارهٔ `claude` / `codex login` را کلید می‌زند. نگاه کنید به
  [بک‌اندها ← آمادگی و آماده‌سازی](/docs/backends#connect-time-readiness--onboarding).
</Note>

## چه کارهایی می‌تواند بکند

عامل (Claude *یا* ChatGPT) مهارت‌های مدلِ comfyui-mcp را بارگذاری می‌کند
(IDEOGRAM، WAN، LTX، Qwen و بیشتر)، پس از قبل مدل‌هایی را که اجرا می‌کنید
می‌شناسد — Claude به‌صورت بومی، و ChatGPT از راه همان دانش که به شکل ابزارهای MCP
در دسترس گذاشته شده ([هم‌ترازی دانش](/docs/tools/skills-knowledge)). می‌تواند
تصویر، ویدیو و صدا تولید کند، ComfyUI شما را بررسی و مدیریت کند، و دربارهٔ
پیکربندی‌تان استدلال کند — و بعد در گفت‌وگوی پنل پاسخ بدهد.

همچنین می‌تواند **یک گردش‌کار یا بستهٔ نصب کامل را در یک حرکت بارگذاری کند**
(`panel_load_workflow pack:<name>`) و **هزینه‌آگاه** است: بسته‌های همراه، محلی/
رایگان روی GPU خودتان اجرا می‌شوند، و برای گرافی که فی‌البداهه ساخته شود عامل
زمان اجرا را بررسی می‌کند (`list_packs` با `action:"check_runtime"`) و **پیش از
خرج کردن اعتبار پولی API می‌پرسد**. نگاه کنید به
[مهارت‌ها، بسته‌ها و هزینهٔ زمان اجرا](/docs/tools/skills-knowledge).

## هدایت گراف زنده

عامل خودگردان از راه یک **فهرست مجاز ثابت** از فرمان‌های `panel_*` روی ComfyUI
زندهٔ شما کار می‌کند — بدون هیچ JavaScript دلخواهی. هر تغییر گراف از مسیر ردیابی
تغییرات LiteGraph می‌گذرد، پس همه‌شان با **Ctrl+Z** برگشت‌پذیرند. همان سطح
`panel_*` برای هر دو بک‌اند یکسان در دسترس است (درون‌پردازشی برای Claude، و از راه
یک MCP روی HTTP لوپ‌بک برای ChatGPT/Codex)، پس [هم‌ترازی](/docs/backends) خودکار
است.

### خواندن

| ابزار | اثر |
|---|---|
| `panel_query_graph` | پرس‌وجو از گرافی که در حال دیده شدن است — فیلتر/پیمایش/تجمیع، با کران توکن |
| `panel_get_subgraph` | خواندن گراف درونی یک گره زیرگراف |
| `panel_view_selected` | خواندن گره‌هایی که کاربر **انتخاب** کرده — با یک فراخوانی به «این گره» پاسخ می‌دهد |
| `panel_view_nodes_in_viewport` | خواندن فقط آنچه **روی صفحه** است (مستطیل ناحیهٔ دید + بزرگ‌نمایی) — کار را روی گراف بزرگ محدود می‌کند |
| `panel_get_errors` | **چرا** یک گره قرمز است — هر گره خطادار به علتش وصل می‌شود (مدل نبوده + نشانی دانلود، رسانهٔ نبوده، اعتبارسنجی، `exception_type` زمان اجرا) |
| `panel_list_workflows` | فهرست زبانه‌های باز گردش‌کار و اینکه کدام فعال است |
| `panel_list_nodes` | فهرست بسته‌های گره سفارشی نصب‌شده |
| `panel_list_mcp` | فهرست سرورهای MCP متصل |
| `panel_get_content_mode` | خواندن وضعیت رضایت محتوای بزرگ‌سال (NSFW) |

### ویرایش گراف (برگشت‌پذیر)

| ابزار | اثر |
|---|---|
| `panel_add_node` | افزودن یک گره بر پایهٔ class_type |
| `panel_remove_node` | برداشتن یک گره |
| `panel_connect` / `panel_disconnect` | وصل/قطع کردن اسلات‌ها بر پایهٔ نام یا اندیس (در `panel_connect` هر دو اسلات را نگویید تا بر پایهٔ نوع خودکار تطبیق شود؛ `auto_match:false` رفتار قدیمی اندیس صفر را برمی‌گرداند) |
| `panel_set_widget` | تغییر مقدار یک ویجت (steps، cfg، پرامپت‌ها، …) |
| `panel_edit_node` | جابه‌جا کردن، تغییر اندازه، تغییر عنوان، تغییر رنگ، تغییر شکل، جمع کردن یا پین کردن یک یا چند گره، به‌صورت اتمی |
| `panel_auto_layout` | چیدن خودکار کل گراف (یا بخشی از آن) در یک چیدمان تمیز جریانی/شبکه‌ای بر پایهٔ توپولوژی پیوندها — `dry_run` برای پیش‌نمایش |
| `panel_clear` | برداشتن همهٔ گره‌ها — کل این پاک‌سازی با یک Ctrl+Z برمی‌گردد |

### زیرگراف‌ها

| ابزار | اثر |
|---|---|
| `panel_select_nodes` | انتخاب گره‌ها روی بوم (انتخاب چندتایی) |
| `panel_create_subgraph` | گروه کردن گره‌های انتخاب‌شده در یک زیرگراف («Convert to Subgraph») |
| `panel_enter_subgraph` | رفتن به درون یک زیرگراف برای خواندن / ویرایش گره‌های درونی‌اش |
| `panel_exit_subgraph` | بازگشت به گراف والد / ریشه |

### چیدمان فضایی

عامل می‌تواند هندسهٔ گره‌ها را ببیند — ردیف‌های جزئیات `panel_query_graph` برای هر
گره `pos`/`size` را برمی‌گردانند، به‌علاوهٔ `rails` ورودی/خروجی زیرگراف، `groups`
و `color`/`collapsed` هر گره — و بوم را با مجموعه‌ای متناظر از نوشتن‌ها بچیند،
سپس از نتیجه **اسکرین‌شات** بگیرد تا دربارهٔ چیدمان خودش داوری کند. یک مهارت
`workflow-layout` این‌ها را در یک چیدمان خودکارِ لایه‌بندی‌شده بر پایهٔ وابستگی و
بدون هم‌پوشانی به هم گره می‌زند که قاعدهٔ اصلی‌اش این است: *همیشه ورودی‌ها و
خروجی‌ها را در معرض دید بگذار* تا بتوانید مستقیم وارد کار شوید.

| ابزار | اثر |
|---|---|
| `panel_move_rail` | جابه‌جا کردن ریل ورودی / خروجی یک زیرگراف تا سیم‌های مرزی کوتاه بمانند |
| `panel_create_group` / `panel_move_group` / `panel_edit_group` / `panel_remove_group` | ساختن، جابه‌جا کردن، تغییر عنوان/رنگ، یا حذف یک جعبهٔ گروه برچسب‌دار (با دادن `node_ids` خودکار دورشان می‌پیچد) |
| `panel_screenshot` | رندر کردن بوم به PNG و برگرداندنش به‌صورت تصویر تا عامل بتواند چیدمانش را وارسی کند |

### زبانه‌های گردش‌کار

| ابزار | اثر |
|---|---|
| `panel_new_workflow` | باز کردن یک گردش‌کار خالی تازه در یک زبانهٔ جدید (هرگز زبانهٔ فعلی را پاک نمی‌کند) |
| `panel_open_workflow` | سوئیچ به یک گردش‌کار بر پایهٔ مسیر / نام فایل |
| `panel_rename_workflow` | تغییر نام یک گردش‌کار |
| `panel_close_workflow` | بستن یک زبانه (اگر تغییر ذخیره‌نشده باشد رد می‌کند، مگر آنکه اجبار شود) |
| `panel_save_workflow` | ذخیره / ذخیره با نام، به‌صورت برنامه‌ای — هیچ پنجره‌ای باز نمی‌شود |

### بارگذاری یک گردش‌کار در یک حرکت

| ابزار | اثر |
|---|---|
| `panel_load_workflow` | جایگزینی گراف زنده با یک گردش‌کار کامل در یک فراخوانی — ترجیحاً از `pack:<name>` استفاده کنید تا گردش‌کار محلی/GPU یک بستهٔ نصب همراه بارگذاری شود، بدون آنکه JSON از میان گفت‌وگو رد شود. گراف جایگزین‌شده یک نقطهٔ بازگشت می‌شود (دو بار Esc / `/revert`). |

### دانش و آگاهی از هزینه

عامل تخصص‌های همراه را کشف می‌کند و پیش از خرج کردن اعتبار، هزینهٔ زمان اجرا را
بررسی می‌کند (همان ابزارها روی هر دو بک‌اند — نگاه کنید به
[مهارت‌ها، بسته‌ها و هزینهٔ زمان اجرا](/docs/tools/skills-knowledge)):

| ابزار | اثر |
|---|---|
| `list_packs` (`action:"skill_list"` / `action:"skill_read"`) | کشف و خواندن مهارت‌های همراه در سطح خانوادهٔ مدل + گردش‌کار |
| `list_packs` (`action:"list"` / `action:"read_workflow"`) | فهرست بسته‌های نصب تک‌فرمانی (محلی/GPU خودتان — رایگان) و خواندن گراف یک بسته |
| `list_packs` (`action:"list_templates"`) | فهرست قالب‌های رسمی گردش‌کار ComfyUI روی سرور متصل |
| `list_packs` (`action:"check_runtime"`) | رده‌بندی یک گراف به **local** (رایگان) یا **api/mixed/unknown** (پولی) — عامل پیش از خرج کردن اعتبار پولی API می‌پرسد |

| `panel_restart_comfyui` | راه‌اندازی دوبارهٔ ComfyUI برای بارگذاری گره‌های تازه — پنل خودکار دوباره وصل می‌شود و عامل کار را از سر می‌گیرد |

### MCP و نشست

| ابزار | اثر |
|---|---|
| `panel_add_mcp` / `panel_remove_mcp` | وصل کردن / برداشتن یک سرور MCP در پیکربندی MCP عامل کاربر (Claude یا Codex) |
| `panel_request_secret` | گرفتن امن یک توکن API — عامل هرگز مقدارش را نمی‌بیند |
| `panel_reload` | بارگذاری دوبارهٔ نرم ارکستریتور (کد/ابزار تازه) یا رابط کاربری پنل، و بعد ادامه دادن |

### کار با کاربر

| ابزار | اثر |
|---|---|
| `panel_ask` | خواستن از کاربر برای انتخاب میان چند گزینه (یک کارت پرسش نشان می‌دهد و تا انتخاب منتظر می‌ماند) |
| `panel_set_todo` | نمایش یک سیاههٔ زندهٔ کارها (TODO) در سینی پایین پنل |
| `panel_request_adult_consent` / `panel_disable_adult_mode` | روشن/خاموش کردن دروازهٔ رضایت +۱۸ (NSFW) |

<Note>
  هر ابزار یک `tab_id` اختیاری می‌پذیرد — هر زبانهٔ مرورگر اتصال خودش را دارد، و
  مسیریابی به‌طور پیش‌فرض به تنها زبانهٔ موجود می‌رود، یا به زبانه‌ای که کاربر آخرین
  بار در آن تایپ کرده است.
</Note>

## عقب بردن و بازگردانی

پیام‌های گذشته منجمد نیستند. نشانگر را روی هر پیامی ببرید و دکمهٔ **✎ ویرایش** یک
پنجرهٔ بازگردانی باز می‌کند: **کد** را بازگردانید (گراف را به اسنپ‌شات همان نوبت
برگردانید)، **گفت‌وگو** را (نشست را از آن نقطه شاخه بزنید)، یا **هر دو** را، و بعد
از همان‌جا پیامی ویرایش‌شده را دوباره بفرستید. بازگرداندن گراف از اسنپ‌شات‌های هر
نوبت استفاده می‌کند، پس لغو یک نوبت دقیقاً همان گرافی را برمی‌گرداند که با آن شروع
شده بود.

دو میان‌بر، حالت‌های رایج را پوشش می‌دهند:

- **`/revert`** — لغو ویرایش‌های گراف در نوبت آخر.
- **دو بار Esc** — عقب بردن سریع نوبت آخر: گراف را برمی‌گرداند و پیام را برای
  ویرایش و ارسال دوباره به کادر نگارش فرا می‌خواند.

<Note>
  بازگردانی **کد** (گراف) روی **هر دو** سرویس‌دهنده کار می‌کند — در ارکستریتور و بر
  پایهٔ اسنپ‌شات‌های هر نوبت پیاده شده است. بازگردانی **گفت‌وگو** (شاخه زدن گفت‌وگو به
  نوبتی در گذشته) فعلاً **فقط روی Claude** است؛ بک‌اند ChatGPT/Codex فقط کل رشته را
  از سر می‌گیرد، پس پنل این دامنه را برایش می‌بندد. نگاه کنید به
  [ماتریس قابلیت‌ها](/docs/backends#capability-matrix).
</Note>

## سینی پیام‌های در انتظار

وقتی عامل مشغول است تایپ کنید و پیامتان در گفت‌وگو گم نمی‌شود — در یک سینی ثابت
**در انتظار** می‌ماند که بالای سینی دانلودها لنگر انداخته، بیرون از جریان گفت‌وگو.
هر پیام در انتظار دکمه‌های **ویرایش**، **همین حالا بفرست** و **حذف** دارد، و یک
دستگیرهٔ کشیدن (≡، سمت چپ) تا **ترتیب** تخلیهٔ آن‌ها به‌دست عامل را عوض کنید.
**همین حالا بفرست** نوبت جاری را قطع می‌کند تا بی‌درنگ مسیرش را عوض کند. وقتی پیام
در انتظار از صف بیرون می‌آید، در **پایین** گفت‌وگو ظاهر می‌شود، پس متن گفت‌وگو دقیقاً
به همان ترتیبی خوانده می‌شود که عامل (Claude یا ChatGPT) پردازشش کرده است.

## تأیید کارهای ویرانگر

کارهای برگشت‌ناپذیر اول می‌پرسند. `panel_clear` (پاک کردن همهٔ گره‌ها) و
`panel_restart_comfyui` یک کارت بله / خیر بالا می‌آورند و فقط با **بله** عمل
می‌کنند — پس عامل نمی‌تواند بی‌سروصدا گراف شما را نابود کند یا ComfyUI را از نو
راه بیندازد.

## پایداری اتصال دوباره

یک ارکستریتور گیرکرده دیگر پنل را بی‌پناه رها نمی‌کند. اگر ارکستریتور پیشین هنوز
درگاه پل را در دست داشته باشد، زدن **اتصال** به‌جای شکست خوردن همان نمونهٔ زامبی را
پس می‌گیرد — پنل دوباره وصل می‌شود، به‌جای اینکه شما گیر بمانید.

## پیوست‌های کادر نگارش

در کادر نگارش پیوست کنید، بکشید و رها کنید، یا بچسبانید. کنار تصویرها، کادر نگارش
اکنون فایل‌های **ویدیو**، **گردش‌کار `.json`** و **متنی** را هم می‌پذیرد، پس
می‌توانید یک کلیپ مرجع، گردش‌کاری برای اقتباس، یا فایل یادداشتی را مستقیم به عامل
بدهید.

## رسانهٔ غنی در پاسخ‌های عامل

وقتی رسانهٔ یک اجرا به عامل بازخورانده می‌شود، خروجی فقط یک بلوک تصویر نیست —
همراهش **فراداده‌ای** می‌آید که عامل می‌تواند دربارهٔ آن استدلال کند: مسیر هر خروجی
(نسبت به زیرپوشه)، اندازهٔ فایل، ابعاد پیکسلی، و **گروه‌بندی مجموعهٔ دارایی‌ها**
(«خروجی K از N در این اجرا» به‌همراه نام فایل‌های هم‌گروهش، یا «خروجی تکی»)،
به‌علاوهٔ مدت رندر و زمان پایان. استوری‌بوردهای ویدیویی، قالب و تعداد فریم / fps
واقعی را هم اضافه می‌کنند، اگر داده‌شان همراه بار ارسالی آمده باشد. به این ترتیب
عامل نتیجهٔ واقعاً ذخیره‌شده را درست نام می‌برد و می‌تواند دربارهٔ اندازه، ابعاد و
تعداد فایل‌های یک اجرا حرف بزند.

## کپی و شکستن خط در بلوک‌های کد

بلوک‌های کد رندرشده یک دکمهٔ **کپی** هنگام بردن نشانگر می‌گیرند و یک کلید سراسری و
ماندگار **شکستن خط** (به‌طور پیش‌فرض خاموش — تا روشنش نکنید خط‌های بلند به‌صورت
افقی اسکرول می‌شوند). کدِ درون‌خطی هم کپی مخصوص خودش را دارد. هر دو با ظاهر پنل
هماهنگ‌اند.

## هشدار گیر کردن رندر

ارکستریتور یک دیدبان منفعل روی صف ComfyUI شما اجرا می‌کند: رندری که گره/پیشرفتش
جلو نمی‌رود **گیرکرده** علامت می‌خورد و به عامل گفته می‌شود (تا کورکورانه کارهای
تازه را پشت یک کار گیرکرده روی هم نچیند). آستانه‌اش تنظیم **هشدار گیر کردن رندر
(ثانیه)** زیر **تنظیمات ← Comfy MCP Agent ← عمومی** است (پیش‌فرض ۱۸۰ ثانیه، بازهٔ
۱۵ تا ۳۶۰۰). این مقدار هنگام اتصال فرستاده می‌شود و **زنده** هم اعمال می‌شود —
تغییرش بدون اتصال دوباره کار می‌کند. نگاه کنید به
[پیکربندی ← `COMFYUI_MCP_STALL_S`](/docs/configuration#panel-orchestrator--the-bridge).

## پایایی در زبانهٔ پس‌زمینه

پاسخ‌های جریانی حالا حتی وقتی زبانهٔ ComfyUI در **پس‌زمینه** است هم رندر می‌شوند.
پیش‌تر اثر تایپی پاسخ روی `requestAnimationFrame` اجرا می‌شد که مرورگر آن را در
زبانهٔ پنهان متوقف می‌کند — پس اگر وسط یک اجرای طولانی چندمرحله‌ای زبانه را عوض
می‌کردید، حباب پیام خالی می‌ماند با یک نشانگر جریانِ گیرکرده، طوری که انگار عامل
«در فکر گیر کرده» است، حال آنکه نوبت تمام شده بود. حالا وقتی زبانه پنهان شود پاسخ
هم‌زمان نهایی می‌شود، و یک هندلر `visibilitychange` هر پاسخ در انتظار را هنگام
پنهان شدن تخلیه می‌کند و هنگام بازگشت، اثر تایپی را از سر می‌گیرد. انیمیشن در
پیش‌زمینه دست‌نخورده است.

## کنترل ابری RunPod

یک **نشان میزبان** در نوار ابزار **🟢 محلی · دستگاه شما** یا **🔵 RunPod · `<pod>` ·
GPU · $/hr** را نشان می‌دهد و یک **کنترل‌پنل RunPod** باز می‌کند: یک کارت وضعیت
زنده (GPU / VRAM / مدت روشن بودن / $·hr / نشانی ComfyUI / شمارش معکوس توقف خودکار
در بی‌کاری)، یک فهرست کشویی که پادهایتان را **با نام** فهرست می‌کند، اتصال / شروع /
توقف / **استفاده از محلی**، و یک **استقرار** که با تأیید مسلح می‌شود. یک بار
`RUNPOD_API_KEY` را در کارت کلیدهای API بگذارید و می‌توانید بدون دست زدن به کنسول
RunPod، یک GPU ابری را مستقر کنید، بپایید، میان محلی⇄پاد سوئیچ کنید و متوقفش کنید
— نشان میزبان همیشه می‌گوید رندر بعدی کجا اجرا می‌شود. نگاه کنید به
[استقرار ابری](/docs/cloud-deployment) و نوشتهٔ وبلاگ
[ComfyUI را روی یک GPU ابری اجاره‌ای اجرا کنید](/docs/blog/runpod-comfyui).

## مرورگر CivitAI

دکمهٔ **Civitai** در نوار ابزار یک مرورگر کامل CivitAI باز می‌کند — تصویرها،
ویدیوها، چک‌پوینت‌ها، LoRAها و گردش‌کارها، با جست‌وجو، فیلتر و یک نمایشگر تمام‌صفحه.
یک نتیجه را انتخاب کنید تا **با عامل هم‌رسانی‌اش کنید**، **روی دستگاهتان دانلودش
کنید**، یا **گردش‌کار جاسازی‌شده‌اش را** روی بوم **ذخیره کنید**. داستانش:
[CivitAI درون ComfyUI](/docs/blog/civitai-in-comfyui).
